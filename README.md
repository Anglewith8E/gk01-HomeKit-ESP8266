# GK01 原生 HomeKit 红外遥控器固件

把小兀 GK01 红外遥控器（中国移动配 App 那款）刷成本项目固件后，它将变成一个**原生 Apple HomeKit 配件**——不需要任何网桥/服务器，直接在 iPhone 的"家庭"App 中添加，可以：

1. **学习**家里电器遥控器的红外信号（任意协议，含空调原始码）
2. 在**家庭 App 里点按按钮发射**红外信号控制电器
3. 收到已学按键的红外码时**反向触发 iOS 自动化**（如"对着 GK01 按电视遥控器 → 关灯"）

参考项目：[summmer121/gk01-ir-receiver-launch](https://github.com/summmer121/gk01-ir-receiver-launch)（ESPHome 方案，红外收发引脚参数来源）；本项目改用 [Mixiaoxiao/Arduino-HomeKit-ESP8266](https://github.com/Mixiaoxiao/Arduino-HomeKit-ESP8266) 实现原生 HomeKit，红外收发使用 IRremoteESP8266 2.8.6。

> **实测状态**：已在一台 GK01 上完整验证——学习/发射（三星家庭影院 NEC 帧、美的空调 COOLIX 帧）、家庭 App 配对、反向联动均正常。资源占用 RAM 48.5% / Flash 59.4%（12 槽位版本）。

---

## ⚠️ 重要：先确认你的 GK01 用的是哪颗芯片

参考项目的作者拆机确认 GK01 主控是 **ESP12F（ESP8266EX，4MB Flash）**，而不是 ESP32（ESP32 是很多资料对这类设备的笼统说法）。本固件按 **ESP8266** 编写。

验证方法（任选其一）：
- 看板上屏蔽罩丝印：`ESP12F` / `ESP-12F` 即为本项目目标硬件
- 串口（115200）上电日志出现 `boot mode:(3,x)`、`load:0x…` 等字样即 ESP8266

如果确认是 ESP32（丝印 ESP32-C3/ESP32 等），**本项目固件不适用**——ESP32 上应改用 [HomeSpan](https://github.com/HomeSpan/HomeSpan) 框架，架构不同，需要另外生成代码。

## 硬件引脚（实测修正）

| 功能 | GPIO | 说明 |
|---|---|---|
| 红外接收 | GPIO5 | 接收头输出低有效，内部上拉 |
| 红外发射 | GPIO14 | 38kHz 载波 |
| 红色 LED | GPIO12 | 发送指示 |
| 黄色 LED | GPIO13 | 接收/学习指示 |
| 实体按键 | **GPIO0** | **板载上拉，按下为低**（实测确认；参考项目文档写的 GPIO16 有误） |

> **GPIO0 兼作 ESP8266 启动模式引脚**：上电/复位瞬间按住按键 = 进入串口下载模式（刷机正好利用这一点，无需找焊点）；但日常使用时不要在上电瞬间按着它，否则设备不会启动，松手重启即可。

如 LED 亮灭相反，把 `include/config.h` 里 `LED_ACTIVE_LOW` 改为 `true`。

## 固件功能设计

配件树（iOS 家庭 App 中一块配件）：

```
GK01
 ├─ 学习模式 (开关)     打开后，下一个收到的红外码存入空的"按键N"
 ├─ 按键1 (开关)        学到的红外码；点按 = 发射
 ├─ 按键2 (开关)        …
 └─ 按键12 (开关)       共 12 个槽位
```

- **学习**：家庭 App 打开"学习模式"（或**短按 GK01 实体按键**），黄灯快闪后用原遥控器对准 GK01 按一下 → 自动存为下一个空槽位，学习模式自动关闭。**槽位永远按 1→12 顺序填充，无法指定**
- **发射**：点按"按键N"即以 38kHz 原始时序回放；**≥150 边沿的空调长帧自动连发两遍**（原装遥控器同样行为，部分空调只认第二遍）
- **反向联动**：收到与已学按键相同的红外码时，对应开关会自动开→关一次，可用它触发 iOS 自动化。匹配分两层：可解码协议按"协议+解码值"精确匹配；**任何码（含 UNKNOWN、解码不稳定的协议）都再做 RAW 时序相似度匹配**（前 48 边沿逐段比对，容差 20%、90% 吻合）——三星、美的等实测均可触发
- 红外码以 RAW 时序保存在 LittleFS（`/slotN.txt`），任意协议可学可发
- **长按实体按键 10 秒**：恢复出厂（清除红外码 + HomeKit 配对 + WiFi 配置）。**按住 3 秒起红灯快闪警告**，此时松手即取消
- WiFi 配网：首用（或配网失败）时开放热点 `GK01-Setup`，captive portal 配网
- LED 含义：黄灯快闪=等待学习；黄灯双闪=学习成功；红灯亮=发射中；红灯快闪=恢复出厂倒计时；红黄齐闪后重启=恢复出厂

### 空调学习技巧（实测美的/COOLIX 协议得出）

空调遥控器发出的不是"开机"指令，而是**完整状态帧**（模式+温度+风速+电源全部编码在内）：

- 想学"开机"：**先用遥控器把空调关掉**，再进学习模式按电源键 → 学到的一帧就是"开机状态"
- 想学"关机"：空调**开着**时学习 → 存的帧就是"关机命令"
- 回放全状态帧是幂等的，重复发送安全（固件已自动连发两遍）

## 刷机步骤

### 方式一：PlatformIO（推荐）

1. 安装 [VSCode](https://code.visualstudio.com/) + PlatformIO 插件
2. 打开本项目文件夹，`pio run -t upload`（或点 ➜ Upload）
3. 串口监视：`pio device monitor`（115200）

### 方式二：GitHub Actions 云端编译

1. 把本项目推到自己的 GitHub 仓库
2. Actions 会自动编译并产出 `gk01-homekit-firmware` 的 `firmware.bin`
3. 下载后本地用 esptool 烧录

### 方式三：直接用 esptool 烧录已编译的 firmware.bin

```bash
# 安装 esptool: pip install esptool
esptool --port COM4 --baud 115200 write_flash 0x0 gk01-homekit-firmware.bin
```

### 烧录接线（USB-TTL，务必 3.3V 供电！）

| GK01 | USB-TTL |
|---|---|
| 3V3 | 3.3V |
| GND | GND |
| RX/TX 交叉接 | TX/RX |
| 实体按键 (GPIO0) | **按住按键再上电**即进入下载模式，松手开始刷 |

> GPIO0 已是板上按键，无需额外接线接地。首次烧录建议先 `esptool --port COM4 --baud 115200 erase_flash`；**日常升级固件不要 erase**（可保留已学红外码和配网数据）。
>
> 串口看启动日志若全是乱码，把监视器波特率换成 **74880**——那是 ESP8266 Boot ROM 的固定输出速率，与刷机波特率（115200）无关。

## 首次配置

1. 上电后手机连接热点 `GK01-Setup`，自动弹出配网页选择你家 WiFi（浏览器访问 192.168.4.1 亦可）
2. 打开 iOS「家庭」→ ＋ → 添加配件 → 「更多选项…」→ 选择 **GK01**
3. 出现"未认证配件"提示 → 选「仍然添加」→ 配对码输入 **`12345678`**（横杠只是显示分组，不用输入）
4. 配对约需 14 秒（ESP8266 的 HomeKit 加密计算较慢，属正常现象）；手机与 GK01 须同一 WiFi 且路由器未开 AP 隔离

## 学习电器遥控器

1. 家庭 App 中打开「学习模式」（或短按 GK01 实体按键），黄灯快闪
2. 用电器原遥控器对准 GK01 接收头按一下目标按键
3. 黄灯双闪表示完成，码自动存入下一个空槽位（按键1→12 依次），学习模式自动关闭
4. 点按对应开关即可控制电器；长按图标可把开关重新命名（如"电视电源"）
5. **每学一个槽位立刻测试**，确认能控制电器再学下一个——没有单槽删除功能，学错只能恢复出厂全部重来

## 已知限制

- 最多 **12 个**学习槽位（受 ESP8266 内存限制，每槽约占 0.3KB RAM；改 `MAX_BUTTONS` 需同步修改 `src/accessory.c` 的宏展开，目前上限 12）
- 未识别协议（UNKNOWN）的原始码：可学习、可发射，也会通过 RAW 时序匹配触发反向自动化（串口日志显示"时序匹配"）
- 修改"按键N"名称需重新刷机或在代码中修改（HomeKit 名字特征更新后 iOS 可能缓存旧值）
- 非 MFi 认证配件无二维码可扫，只能手动输码添加
- 换 WiFi 环境后若 HomeKit 连不上，先重启设备；仍不行则长按 10s 恢复出厂重新配对
- 更换槽位数量的固件后，配件树结构变化，需在家庭 App 中删除配件重新配对

## 故障排查

| 现象 | 处理 |
|---|---|
| 串口乱码 | 监视器波特率 115200；看 Boot ROM 日志用 74880 |
| 上电即重启循环 | 供电不足，换 ≥500mA 的 3.3V 电源 |
| 家庭 App 搜不到配件 | 等待 preinit 约 9 秒；确认手机与设备同一 WiFi；路由器未开 AP 隔离 |
| 添加配件"未响应" | 删除家庭 App 里的旧配件再重新添加；确认上电后等待 15 秒以上再配对 |
| 配对中途失败 | CPU 必须 160MHz（`platformio.ini` 已配置）；重新上电再试一次 |
| 学到的码无法控制电器 | 发射时红灯应亮；距离缩短到 20cm 内正对电器接收口；空调码确认学习时空调处于目标状态（见"空调学习技巧"）|
| 电器"滴"一声但没动作 | 空调全状态帧方向学反了（开着时学的变成关机命令），按"空调学习技巧"重学 |
| 机身按键无反应 | 上电瞬间的按键不响应（GPIO0 启动模式）；运行中短按应有"实体按键按下 (GPIO0)"串口日志 |
| 设备无故重置/要求重新配网 | 若按住按键超 10 秒会恢复出厂（红灯快闪=倒计时警告）；确认为误触发则注意长按时间 |
| LED 亮灭颠倒 | `LED_ACTIVE_LOW` 改为 `true` |

## 技术要点（给想改代码的人）

- IRremoteESP8266 **v2.8.x** 的 `rawbuf` 单位是 **2µs**（边沿中断实现，库常量 `kRawTick`）——不是老版本的 50µs/tick，换算错误会导致时序放大 25 倍并溢出（本项目曾踩过的坑）
- 常见协议枚举值（v2.8.6）：NEC=3、SAMSUNG=7、COOLIX=15（美的空调）、COOLIX48=110
- 官方 HomeKit 库自带 `base64.h` 会遮蔽 ESP8266 core 的同名头文件导致 WiFiManager 编译失败，本工程已将其改名 `hk_base64.h` 并更新库内 3 处引用
